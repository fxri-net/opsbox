## 安装与环境

### 怎么安装？

本工具集已发布到 npm，按场景三选一：

```bash
pnpm i -g @fxri/opsbox          # 全局安装（推荐个人多项目）
pnpm add -D @fxri/opsbox        # 项目 devDependency（推荐团队项目）
pnpm dlx @fxri/opsbox --help    # 不安装、临时执行
```

安装后 `opsbox --help` 可查看命令树；三种方式的取舍与 npm / yarn / bun 等价命令见[新手指南 · 安装](./getting-started#安装)。

### 支持哪些平台？

Linux / macOS / Windows 全平台。平台在运行期自动探测，无需手工指定；数据目录、二进制目录、服务名等默认值随平台给出，均可经命令选项覆盖。

| 平台 | 适配层 | 服务控制 | 权限复位 |
| --- | --- | --- | --- |
| Linux | unix | `systemctl` → `brew services` → `mysql.server` | `chown -R mysql:mysql` |
| macOS | unix | 同 Linux | 跳过 |
| Windows | windows | `sc` → `net` | `icacls /reset` |

### Node 版本有什么要求？

正式支持 **Node.js >= 20.19.0**。低于该版本不在支持范围内。

### 某个平台上的默认路径不对，能改吗？

能。默认值只是「未配置时的回落档」，按优先级用命令行选项（`--data` / `--bin` / `--backup` / `--staging`）或[配置文件](./config)覆盖即可。

## MySQL 库恢复

### `restore` 提示缺少产物清单怎么办？

`restore` 依赖 `ddl` 阶段产出的 `manifest.json`。缺失时命令以明确中文错误终止——先执行一次 `ddl`，再用同一 `--work`（缺省 `.opsbox`）目录跑 `restore`。

### 恢复前想先看看会做什么，可以吗？

可以，两阶段都支持预演：`restore --dry-run` 仅做前置校验并打印执行计划，不落盘。先看清动作再决定是否执行。

### `restore` 会改动数据目录吗？有备份吗？

默认对数据目录做**整目录冷备**再操作，可用 `--backup` 指定备份目标。若确认无需备份可 `--skip-backup`（跳过冷备，风险自负）；`--skip-validate` 跳过恢复后校验。

### 口令怎么传？

`restore` 缺省走**交互式掩码输入**；非交互终端拒绝读取，此时用 `--password` 传入。⚠️ 命令行传口令会留在 shell 历史里，交互场景优先用交互式输入。

### 只恢复其中几个库，能行吗？

`ddl` 阶段用 `--only <lib>`（可多次传入）限定要处理的库，缺省处理全部；`restore` 依 `ddl` 的产物清单执行。

## 项目目录改名

### 改名时提示宿主未关闭怎么办？

`project-rename` 迁移前须**先关闭目标宿主**（IDE / 编辑器）——否则宿主正在写入的状态会在迁移中丢失或被覆盖。关闭后重跑即可。

### 为什么要跑两趟？

新工作区 id 由宿主生成、不可提前推算，因此拆成两趟：**第一趟**改写文本载体、搬迁目录并备份二进制状态；等宿主重新生成新 id 目录后，用 `--resume` 做**第二趟**，按清单把二进制状态副本落位并清理旧工作区目录。

### 只想迁移某个宿主，可以吗？

可以。`--host <id>`（可多次传入）限定迁移的宿主；缺省迁移全部检出宿主。

### 出错了能回滚吗？

默认迁移前**先备份**，出问题可据备份恢复。`--no-backup` 跳过备份（危险：将无法回滚），仅在明确知晓后果时使用。先用 `--dry-run` 预览迁移计划是更稳妥的做法。

### 交互确认能跳过吗？

可以，`--yes` 跳过交互确认，适合脚本化调用。

## 配置

### 配置文件放哪？三层有什么区别？

全局层 `~/.opsboxrc.json`（个人跨项目）、项目层 `.opsboxrc.json`（团队共享、随仓库走）、本地层 `.opsboxrc.local.json`（个人按项目、默认被 git 忽略）。定位规则、合并粒度与覆盖链见[配置参考](./config)。

### 配置改了没生效？

配置读取有进程级缓存：长驻进程或测试中改配置后需重新执行命令。另外确认字段类型正确（`updateCheck.enabled` 须布尔、路径类须非空字符串）——类型不符会按未写处理并告警。跑 `config status` 可只读查看三层命中与来源层，快速定位。

### 怎么关掉升级提示？

二选一：环境变量 `OPSBOX_NO_UPDATE_CHECK` 设为真值（如 `=1`），或配置文件 `updateCheck.enabled` 设为 `false`。两者都设时环境变量优先。`0/false/off/no` 视为未关闭。

### 内网 / 离线环境会不会卡住？

不会。升级检查的联网在**分离的后台子进程**里做，父进程零网络、不等待结果，不阻塞命令、不影响退出码；离线时查询静默失败并记负缓存。也可以直接用上面两种方式关闭。

## 升级

### 怎么升级？

按安装形态升级：

```bash
pnpm i -g @fxri/opsbox                 # 全局安装（npm 用户 npm i -g @fxri/opsbox）
pnpm add -D @fxri/opsbox@latest        # 项目 devDependency
```

若以库形态引入，则按依赖方式更新 `@fxri/opsbox` 到目标版本。
