# 全端通用规范（common）

> 归属：common（所有端适用）。条文全文见本节，索引见 index.md。

## C-1. 能力全平台

所有能力默认须跨平台（Linux / macOS / Windows）。

- 平台差异统一经适配层隔离：平台无关核心不得直接调用平台特有命令或路径（如 `systemctl` / `net` / `D:\...`）
- 新增能力须同步给出各端适配实现；确不可跨平台者，须在能力文档显式声明支持的平台与降级范围
- 平台探测在运行期完成，不依赖编译期条件或用户手工指定

## C-2. 真实信息零泄漏

任务区（`.tasks/`）与逻辑代码（`src/` 等）不得出现真实环境标识与凭据。

- 禁止项（通用口径，不限于所列举）：
  - 真实数据库 / 表 / 账号 / 口令 / 密钥 / token
  - 真实主机名 / IP / 端口 / 域名 / 实例标识
  - 机器特有的绝对路径与本地目录布局
  - 生产数据样本（真实字段值、真实业务数据）
  - 客户 / 项目 / 公司代号及其它可定位到具体主体的名称
  - 其它可据以还原某台机器或某套环境的信息
- 允许项：厂商文档化的通用约定（如 Linux 宝塔 `/www/server`、Homebrew `/usr/local/opt`）与协议固定值（如 `127.0.0.1` / `root` / `mysql`）
- 需要真实输入时参数化（`--data <dir>`）或占位（`<db>`），运行期从环境推导，不写死
- 范围限于任务区与逻辑代码；`package.json` / `LICENSE` 等元数据文件不在此列
- 归档块原则上不可变；确需脱敏更正时原位改写并在块内留痕

## C-3. 能力维度组织

能力（capability）目录按「做什么」切分，不按宿主 / 工具 / 平台切分。

- 目录名即能力名（如 `mysql-recover`），描述用户目标；不得以宝塔 / trae 等宿主或工具命名
- 宿主 / 平台差异经适配层隔离（见 `C-1`），不进能力目录名
- 能力跨宿主可复用时须保持宿主无关（如 MySQL 重装后恢复与是否宝塔无关）
- 新增宿主支持时只扩适配层，不新增能力目录

## C-4. 自定运行期产物收口

本工具自定的运行期产物统一落项目根下的隐藏目录 `.opsbox/`（以工具名命名，对标 `.terraform/` / `.turbo/` 等惯例）。

- 落点由命令默认值给出，可经选项（如 `--out` / `--work`）覆盖；不得默认散落于项目根
- Node 生态标准产物（`node_modules/` / `dist/` / `coverage/`）受生态约定约束，保持根目录默认位置，不强行收口
- `.opsbox/` 属可确定性重生成的运行期产物，按 `.gitignore` 排除、不入库

## C-5. 对外内容限本仓产品域

面向用户的对外内容（文档站页面与导航、README 等）只承载本仓产品域的内容。

- 镜像同源姊妹项目（如 `@fxri/toolkit`）的「工程化外围」时须甄别：通用工程基础设施（CI、CHANGELOG、文档站骨架等）可搬；对方的**产品内容**（AI 协作规则、提交信息规则、任务流程等）不得镜像为本仓产品内容
- 判据：该内容是否描述本仓这个工具怎么用——否者即为领域错位，应剔除或改写
- 本仓自有的开发域资产（`AGENTS.md` / `.trae/rules/` / `.tasks/` 等）不受此限：其本就服务本仓开发者、不面向产品用户
