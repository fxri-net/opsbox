## 背景

2. 调整后顺序：安装 → 并行检查（类型 / 静态 / 日志镜像 / 文档主题）→ 单测与覆盖率 → 构建 → 文档站 → CLI 冒烟。

## 20261104-唐启云-CI补手动触发与门禁提速

# CI 补手动触发与门禁提速

批次：本仓本轮门禁与 CI 收敛（前置：无）

## 背景

1. 两个工作流只有 `push` / `pull_request`，平台丢事件时无手动补跑入口。
2. 聚合门禁有四处可省的时间：单测与覆盖率把同一批测试跑两遍；每次全量安装依赖；每次全量构建文档站；类型检查、静态检查、日志镜像核验、文档主题核验四者互不依赖却串行。

## 实施方案

1. `.github/workflows/ci.yml`、`.github/workflows/deploy-docs.yml` 各增加 `workflow_dispatch:`，附一行中文注释；部署工作流现有「不做 paths 过滤、每次全量重建」策略不变。
2. `scripts/verify.mjs`：
   - 单测与覆盖率合并为一次 `vitest run --coverage`；`--skip-coverage` 时同一命令去掉 `--coverage`，检查项不减。
   - 安装条件化：本地 `pnpm-lock.yaml` 不比 `node_modules/.pnpm/lock.yaml` 新时跳过；CI 与 `--full` 永不跳过。
   - 文档构建条件化：本地仅在改动触及 `docs/`、`src/`（站点配置直接引用源码侧信息）、`README.md`、`package.json`、`pnpm-lock.yaml` 时执行；CI 与 `--full` 恒执行。
   - 并行组：`typecheck` / `eslint` / 日志镜像核验 / 文档主题核验四者并发（均不依赖 `dist`），输出按顺序回放；`build` 与后续 CLI 冒烟仍串行。
   - eslint 本地 `--cache`、CI 与 `--full` 用 `--no-cache`。
   - 跳过时输出 `⊘` 与原因，不静默。
3. 覆盖率阈值沿用现值，不放松。
4. 不建变更集：门禁编排与 CI 配置改动，用户不可感知。

## 影响范围

- 代码：`.github/workflows/ci.yml`、`.github/workflows/deploy-docs.yml`、`scripts/verify.mjs`。
- 无触达：`src/` 实现、`docs/` 手写页（生成物不动）、`README.md`、`SPEC.md`。
- 变更集：不建（用户不可感知）。

## 验证方式

- 优化前后各记一次完整运行时长，写入实施结果。
- `CI=1` 与 `--full`：安装、文档站、冷缓存均全量执行。
- 本地无相关改动：安装与文档步骤跳过并打印原因；触及 `src/` 时文档自动执行。
- 注入一处失败：并行组任一失败仍被记录并聚合报出。
- `pnpm verify` 全绿（归档后复跑）。
